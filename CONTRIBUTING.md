# Contributing

Thank you for your interest in the project. Bug reports, improvements, and general feedback are welcome.

This project is developed and maintained by a single person, so my time for reviewing and maintaining contributions is limited. To make the best use of everyone's time, please read the following guidelines before submitting changes.

## Discuss changes before working on them

**Please open an issue to discuss a proposed change before starting work on it.** This is especially important for new features, significant refactoring, architectural changes, or changes that affect existing behavior.

Discussing it first helps establish whether a change is wanted and how it should be implemented before anyone invests time in it.

Opening an issue does not guarantee that a proposal will be accepted, but it gives us an opportunity to agree on the direction before work begins.

## Keep changes focused and simple

I value straightforward and maintainable solutions over unnecessary complexity.

- Solve the actual problem without introducing unrelated changes.
- Prefer the simplest solution that fits the project's existing design and conventions.
- Avoid unnecessary abstractions, dependencies, generalization, or refactoring.
- Keep pull requests focused on a single issue or objective.
- Avoid reformatting or rewriting unrelated code as part of a change.

## AI-assisted contributions

Using AI tools to help write, understand, or review code is fine. However, **you are responsible for the code you submit, regardless of how it was written.**

Before opening a pull request, please make sure you:

- Understand the changes well enough to explain how and why they work.
- Have reviewed the generated code rather than accepting it blindly.
- Have tested the changes where practical and considered potential regressions.
- Can respond to questions, explain design decisions, and make adjustments during review.

AI-generated code can be unnecessarily complicated, introduce needless abstractions, or solve a different problem from the one intended. Please take the time to simplify and adapt it to the project's needs.

These expectations apply to all contributions, whether written by hand, with AI assistance, or through a combination of both.

## Pull requests

Before submitting a pull request:

1. Make sure the proposed change has been discussed and its general direction agreed upon, where appropriate.
2. Keep the diff as small and focused as reasonably possible.
3. Explain the problem being solved, the approach taken, and any relevant design decisions.
4. Include relevant testing information and note any limitations or outstanding concerns.
5. Be prepared to discuss the implementation and revise it in response to feedback.

Pull requests may be declined if they don't align with the project's goals, introduce unnecessary complexity, duplicate existing functionality, or aren't a good fit for the project's maintenance constraints. I may also close a pull request if the proposed change hasn't been discussed beforehand and would require substantial rework or a different approach.

## Review and maintenance

I maintain this project in my spare time, so reviews may take time, and I cannot guarantee that every issue or pull request will receive an immediate response.

## Thank you

I appreciate everyone who takes an interest in this project. You don't need to submit code to contribute something valuable: reporting bugs, suggesting improvements, asking questions, and helping clarify documentation are all welcome.

If you have an idea, **please open an issue and let's discuss it first.** I'd much rather help shape a good solution together than have you spend time building something that ultimately doesn't fit the project.
